Figma 局部主题含 11 个原始颜色、11 个语义别名、9 个间距/圆角变量和 6 个文本样式。按钮组件 `Script/Button` 提供 primary、secondary、danger、disabled 四种状态，Label 为文本属性。删除图标复用 Material 3 可编辑组件。已检查当前仓库无对应 Code Connect 映射；可用通用组件库的按钮字体、形状与确认稿不一致，因此使用上述局部按钮组件。

窄屏规则：宽度不足 1200 px 时连续性区域下移或可折叠；不足 768 px 时集/场使用选择器，正文单列；阶段栏仅自身横向滚动，不使页面产生横向溢出。手机保持保存/提交操作容易触达，弹窗宽度不超过视口减 32 px。

## 交互与业务约束

1. 顶部五阶段直接切换工作内容。完成标记必须来自真实确认状态，不能因为点击过阶段就标记完成。离开未保存内容时保留草稿并提示用户。
2. 立项保存题材、受众、制作边界、单集时长和对白配额。简报与一句话梗概分别编号，在确认框中逐项显示具体编号，再由用户确认整个设定快照。27 秒 / 4 句、210 秒 / 20 句均是作品配置，不是全局限制。
3. 设定包含角色稳定 ID、定妆、声线、称呼、角色已知信息与未回收悬念。先定结局，再写各集开场 3 秒、当集改变与集尾交接。分集大纲分别编号，并纳入同一设定快照的明确确认。
4. 逐集编写从左侧选集和场次；正文记录内外景、日夜、出场角色、动作、对白、声音，台词绑定角色 ID。右侧显示接上集、开场 3 秒、集尾交接及制作资格，并能返回系列圣经。第 2 集起核对已锁前集和连续性信息。
5. 估时包含对白、动作、停顿；明示估算而非真实音频时长。保存草稿不自动通过审稿。提交审稿后在审稿阶段检查身份、目标、当下困境及跨集/素材影响。
6. 定稿页列出简报、梗概、大纲、所选单集正文的具体版本。用户查看后明确确认并锁定正文；后续修订另存新草稿。分镜、配音、视频入口以该集正文的真实锁定版本为依据，服务端同样检查资格。
7. 草稿行右侧删除入口打开确认框，至少显示作品、集数、版本。确认后移入回收站；失败时保留正文和原选择，不假装删除成功。
8. 整部作品从“我的作品”删除，确认框显示涉及集数。回收站列出作品及稿件，恢复后保留历史版本关系；恢复草稿不等于定稿。
9. 已锁定稿件的删除入口放在版本记录。先显示引用的分镜、配音、视频；存在仍在使用的引用时禁用删除并说明原因。引用变化必须在服务端提交时重新检查，不使用旧页面计数直接删除。
10. 弹窗支持 Escape、焦点限制与关闭后焦点归还。危险动作和取消按钮分开，删除不使用主色。每次写入有进行中状态以避免重复提交。

## 状态与验收

- 加载：保持布局与骨架，不将未加载内容当成空数据。
- 空白：说明该集尚无正文，提供新建场次入口。
- 错误：保留未保存文本，显示可理解的原因及手动重试操作。
- 选中：阶段、集、场均有浅绿背景与文字标识，不只靠颜色区分。
- 登录：复用站点登录流程，返回原作品/集数，按现有草稿机制保留未保存内容。
- 冲突：旧版本提交被拒绝后保留本地内容，不能静默覆盖更新。

Figma 已检查五阶段、删除确认、版本引用、回收站、手机和状态画板截图；修复过表单行高、标题和操作栏重叠。最终结构检查没有非预期子元素越界，残留 placeholder 为 0；390 个可编辑文本节点、65 个组件实例，所有正文使用 Noto Sans SC。手机阶段栏裁剪属于预期的横向滚动示意。

上述只证明设计稿检查完成。真实页面截图对照、按钮交互、服务端门禁、删除恢复与并发行为，需要以本次实现的测试和验收记录为准；本文件不宣称生产已部署。
