# 千问网页调用规则（待审查，未实现）

当前可以交付的是本机 `qwen:writing`。它生成 `candidate.json`，由创作者粘贴到编剧助手。网页没有生成按钮，API 没有模型路由，数据库没有模型请求表。

本文只固定还不能编码的原因，以及审查通过后必须遵守的状态规则。它不是已完成功能。

## 不能现在接按钮

1. 商业计划把账户隔离列为后续。仓库没有登录。一个无鉴权的生成接口会变成开放的付费代理。
2. [`PROVIDER_CONTRACTS.md`](PROVIDER_CONTRACTS.md) 规定，只有 `REPLAY_SAFE_SYNC` 能进入现有文本 Job。千问在超时、断连、重定向或响应截断后，结果和费用都不确定。本地 `runId` 不是服务商幂等保证。因此不能把千问标成 `REPLAY_SAFE_SYNC`，也不能替换 `MockTextAdapter`。
3. 官方 chat completions 这一次请求没有被确认成可查询、可补结果的异步任务。在这一点确认之前，不能在超时后自动再 POST。

## 审查通过后的请求身份

建议的持久化记录先叫写作模型请求。它不是故事或剧本修订。

字段至少包括：工作区、操作者幂等键、模式（故事或分集）、分集号、已校验输入的 SHA-256、请求模型、状态、服务商请求 ID、候选是否通过网页同一套解析、费用状态。费用金额保持空，状态保持未知。不保存 API Key、Authorization 或原始错误正文。

状态只有：`reserved`、`submitted`、`completed`、`rejected`、`unknown`。

规则：

1. 发出网络请求之前，在同一事务里占用幂等键并写入 `reserved`。同一键再次出现时返回原记录，不再调用模型。
2. 请求离开进程后才记为 `submitted`。一次操作最多一个请求。
3. 只有 `finish_reason=stop`，并且 `parseWritingImport` 与 `formatWritingImport` 都通过，才记为 `completed`。候选可以被人导入，不会自动写成已保存版本。
4. 认证失败、拒绝、工具调用、非 stop、校验失败记为 `rejected`。不自动第二次请求。
5. 超时、断连、重定向、响应超限，以及请求发出后的 5xx，记为 `unknown`。文案说明可能已经产生费用。不自动重试，不自动换模型。新的调用必须使用新的幂等键，并要操作者明确确认。
6. 采纳候选仍走现有草稿和「保存新版本」。If-Match、409 和审核状态机不变。

## 需审查后才能编码的决定

1. 谁可以花费额度。当前没有账户、配额或价格。
2. `unknown` 能否只用已保存的服务商请求 ID 做查询，而不是再生成。需要官方查询语义的确认。
3. 通过校验的候选存在对象存储还是数据库，以及保留多久。
4. 是否新增 Migration。确认前不写迁移，也不执行迁移。

这四项没有结论时，网页调用保持不实现。
