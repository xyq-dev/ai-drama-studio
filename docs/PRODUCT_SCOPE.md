# AI Drama Studio V1 产品范围

## 产品定位

AI Drama Studio 是面向个人创作者的 Web 工作台：把一个故事创意逐步产出为三集、每集 60–90 秒、1080x1920 的可发布 MP4 竖屏短剧。系统负责可审计的创作与生成编排；创作者始终保有审阅、选择版本和局部重生的控制权。

## 目标用户

- 独立短剧创作者：从创意完成首版短剧，不要求掌握模型工作流。
- 小型内容工作室的单一操作者：需要逐镜头追踪成本、版本和失败原因。

V1 是单工作区、单操作者体验。`workspace_id` 是数据隔离预留字段，不提供租户管理、成员或协作能力。

## 核心用户路径

1. 创建项目并录入创意、题材、受众和约束。
2. 生成故事设定和三集剧本；逐集完成剧本审核。
3. 从已审核剧本提取角色，维护角色设定并生成/选择角色参考图；审核角色设定及选定参考图。
4. 生成场景、镜头与分镜预览图，编辑或仅重生一个镜头；审核分镜后才可提交视频生成。
5. 为镜头生成图片、视频、配音、字幕和背景音乐；查看每次尝试、成本和错误。
6. 合成每集和全剧竖屏成片；人工审核成片后导出 MP4。

## V1 范围

包含：项目、故事设定、三集剧本、角色提取与设定/参考图、场景和分镜、逐镜编辑/重生、图像、视频、配音、字幕、背景音乐、合成、任务/错误展示、成本记录、MP4 导出。

固定产出约束：每项目三集；每集 60–90 秒；1080x1920 MP4。所有生成均应可重试、可追溯，并保留历史版本。

## 非目标

- 红果、抖音或其他平台的自动发布；收益统计或会员支付。
- 多租户 SaaS、多人实时协作、手机 App。
- 模型训练、LoRA 管理平台、素材交易市场。
- 一次处理 30–100 集的批量生产。

## 验收标准

1. 单一创意可走完三集从故事到导出的闭环；审核节点阻止未经确认的剧本、角色或分镜进入后续受控步骤。
2. 任何生成任务能展示状态、尝试记录、标准化错误、输入快照、提供方/模型、耗时和成本。
3. 修改上游内容不会覆盖历史版本，受影响下游资产会被标记 `STALE`；用户可按镜头范围重生。
4. 成片导出仅使用已确认且非 `STALE` 的输入，结果是 1080x1920 MP4，并保留来源关系。
5. Redis/BullMQ 或 Provider 的瞬态状态丢失后，Worker 能以数据库记录恢复可执行工作。

## 关键术语

| 术语 | 定义 |
| --- | --- |
| 项目（Project） | 一部三集短剧的业务根实体。 |
| 修订（Revision） | 不可变的内容版本；新编辑创建新修订，绝不覆盖已使用的修订。 |
| 资产（Asset） | 对象存储中的图片、视频、音频、字幕或导出文件及其数据库元数据。 |
| 生成任务（GenerationJob） | 数据库中可恢复、可取消的业务任务；队列消息只是其调度信号。 |
| 尝试（JobAttempt） | 一次实际 Provider submit 或本地执行器正式执行的审计记录；query、poll 与 callback 记录为 ProviderEvent。 |
| 工作流运行（WorkflowRun） | 一次跨多任务的用户意图，例如“生成角色参考图”。 |
| 已确认（APPROVED） | 人工明确允许该内容作为后续受控步骤输入的状态。 |
| 陈旧（STALE） | 输入版本已不再与资产/下游内容的来源快照一致，不能用于最终导出。 |
| inputHash | 经规范化后输入快照、来源版本和模型参数的 SHA-256；用于去重与幂等。 |

## 审查后范围与术语基线（本节优先）

本文件与其余 V1 文档使用同一术语：`Project → Episode → Scene → Shot` 是稳定身份层级；`StoryRevision`、`ScriptRevision`、`CharacterRevision`、`SceneRevision` 与 `ShotRevision` 是不可变内容版本；`Asset` 是项目内的媒体对象元数据；`GenerationJob` 是一个能力调用；`WorkflowRun` 是一次完整或局部的用户制作意图。一次局部重生也会创建新的 `WorkflowRun`，但只包含该范围所需的 job。

V1 的人工门槛固定为三个阶段：剧本门槛；视频生成前门槛（角色及其选定参考图、以及 ShotRevision 分镜均已审核）；成片导出门槛。角色参考图生成只要求来源剧本已审核、CharacterRevision 非 `STALE` 且输入有效，不要求角色预先审核；分镜预览图也可在最终分镜审核前生成。用户对成功结果主动重新生成使用相应内容生成端点并设置 `bypassCache=true`，不属于 job retry。任何未来的发布、支付、协作、训练、SaaS 或 30–100 集能力均为 `FUTURE`，不是 V1 待办事项。
