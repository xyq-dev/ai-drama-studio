## 已实现

| 范围 | 当前行为 |
| --- | --- |
| 五阶段 | 立项、设定与大纲、逐集编写、审稿修订、定稿交接；从“我的作品”进入 `/projects/[projectId]/script` |
| 立项 | 题材、受众、制作边界、梗概、单集目标秒数及对白配额按作品保存 |
| 系列圣经与大纲 | 结局、角色稳定 ID、定妆、声线、称呼、角色已知信息、未回收悬念；分集开场、改变和交接 |
| 逐集编写 | 集与场次导航；内外景、日夜、出场角色、动作、对白、声音与停顿；对白绑定有效角色 ID |
| 连续性 | 第 2 集起引用前集已锁具体版本；服务端校验前集及交接，改稿使依赖旧版的后集和制作来源失效 |
| 审稿 | 共享估时函数、对白用量、五项人工审稿检查；超额可存草稿，不能直接批准 |
| 明确版本定稿 | 简报、梗概、系列圣经、大纲分别编号，用户确认包含具体编号的设定快照；单集正文另行确认具体版本 |
| 制作交接 | 复用原有审核和制作门禁；分镜、配音、视频链接定位到该集现有制作区域 |
| 草稿和历史 | 每次保存创建原生不可变版本；历史内容可载入为修订草稿，另存新版本；旧纯文本不会读取即重写 |
| 删除与恢复 | 草稿行删除、版本记录删除、作品列表整部删除；确认框显示作品/集数/版本及引用明细；“我的作品 → 回收站”恢复 |
| 删除保护 | 被后集、分镜、配音或视频引用的稿件禁止删除；活动任务中的作品禁止归档；恢复稿件不覆盖当前稿、不自动批准 |
| 请求保护 | 沿用站点登录、工作空间和 CSRF；保存使用版本比较及幂等键；写入期间禁用编辑，冲突保留输入 |

## 上线前的必要动作

删除字段与归档保护触发器已经写入 `packages/database/prisma/drafts/20261111000300_script_workbench_trash.sql`，仅在隔离临时测试库执行。没有放入自动 Migration 目录，没有执行生产 Migration，也没有修改生产数据。生产缺少该结构时，回收站会明确返回 `WORKBENCH_UNAVAILABLE`；不能仅替换前端就当作本功能上线。

Git 提交、推送、PR 与通过 CI 后的合并按本次授权推进。当前执行环境没有服务器 SSH 身份、主机配置或部署连接器，仓库也没有可调用的服务器部署 workflow，因此服务器部署尚未执行。

上线交接必须先核实实际服务器 SHA、数据库迁移台账及备份，完成数据库草稿的正式发布审查，再部署同版 API/web。此草稿不具备重复执行能力，不能裸执行多条 SQL；需要受控事务、重复执行保护和升级前后验证。代码回退不回退数据库，也不能仅更新页面后声称回收站已上线。应在独立 release 目录完成构建，保留上一版，再切换服务并记录 health、页面和实际运行 SHA。

估时仍是写作估算；“陌生观众是否理解”由用户实际审稿判断。工作台快照显示最近 100 个版本，更早版本保留在既有分页接口。系列模式继续受原有仅文本规则约束。
