# AI 自动创作（2026-10-18）

用户只填一句想法、只选题材，或什么都不填，确认规模和调用预算后点一次「AI 自动创作」。服务端自动完成：

资料整理 → 研究与受众分析 → 原创选题比较与规则选择 → 故事与结局、人物关系、地点道具 → 分集大纲 → 逐集剧本 → 程序检查 + 独立 AI 审阅 → 最多两轮定向修改 → 保存为「AI 自动生成草稿」并导出成品剧本包。

本功能交付**剧本包与生产准备包**，不生成图片、语音或视频；「剧本包完成」与「视频成片完成」是两个状态，后者在本功能里永远是「未开始」。

## 1. 为什么不复用 `title_writing_*` 表（实施前核验）

| 方案 | 结论（代码依据） |

| 在 `title_writing_step` 增加新步骤 | `step_key` 的 CHECK 先由 `20261011000100_episode_plan` 改写，又被 `20261012000100_script_breakdown`（测试站未执行）**按名字 DROP 再重建**。新迁移若再改它，拆解迁移日后执行时会把新步骤键删掉；先后顺序还取决于服务器上拆解迁移是否已执行。风险不可控。 |
| 用 `run_kind` 区分 | `run_kind` 列来自拆解迁移，测试站没有。 |
| 新表 + 复用发送原语（采用） | 与 `writing_candidate_request` 的既有做法一致：独立表，复用 `sendWriting`、三家适配器、单次发送不重试、预约→提交→完成协议、租约与执行者隔离、`legacy DeepSeek` 保护；与标题创作、在线候选**共用**工作区调用锁、24 小时调用上限和并发上限。 |

引擎 `AutoCreationEngine`（`packages/providers/src/auto-creation-engine.ts`）只负责自动创作的阶段编排；发送、解析、错误分类、费用 unknown 都来自已验证的 `text-writing.ts`。没有第二套发送实现。

## 3. 研究层：只说真正读到的

- 三个官方入口（巨量引擎帮助中心 1 条、巨量学堂课程 2 条）2026-10-18 实际请求得到的是**前端脚本渲染的空壳**，没有标题或正文。内置快照如实记为 `unreadable / readScope=none / excerpt 空`，不能被引用。
- 项目知识库条目 `S-KB-CRAFT`：本仓库从 drama-skills（MIT，commit c2426e0）改编的写作方法原文，只涉及结构与节奏，**不含任何受众或市场数据**。
- 公开页面读取：`AUTO_CREATION_RESEARCH_FETCH=true` 才开启，只读白名单主机（默认两个官方主机）。仅 https/443、拒绝 IP 字面量和带账号的地址、DNS 结果命中回环/私网/链路本地/共享地址/元数据/组播即拒绝（IPv6 先解码成 8 组，任何写法的 IPv4 映射、兼容、NAT64、6to4 地址都按其中的 IPv4 判断）、连接钉在已检查的 IP（防 DNS 重绑定）、不跟随重定向、512 KB 上限，以及与是否持续收到数据无关的 8 秒绝对截止。外部文字放在标明「不可信」的数据块里，提示词要求忽略其中任何指令。
- 没有视频画面或音频理解能力：所有参考内容只按文字分析，页面和剧本包都写明「没有观看任何视频」。
- **程序校验（拒收而不是提醒）**：引用必须是快照中**已读取**的条目；事实的 `evidence` 必须在所引资料原文中找到；任何数字（含「百分之六十」「18 岁」「3 万」「两成」等）必须出现在所引资料原文里，没有来源的假设、受众、机会中不能出现数字；资料有限模式下受众一律不能标为「有来源」（即使引用了可读但无日期或过期的市场页面）。
- 只有可读、带发布日期、一年内的市场资料才算「有来源」；否则进入**资料有限策划模式**，开始页、运行页和剧本包都明示「不是实时市场验证」。以当前内置快照，默认就是这个模式。

## 4. 质量检查与有限修改

- 程序检查（`deterministicFindings`）：缺集、场次上限（60 秒 ≤5 场，90 秒 ≤7 场）、台词字数（≈5 字/秒）、镜头计划秒数在目标 60%–140%、仅被提及的人物出场、禁止题材、全剧出场人物数和地点数上限、跨集重复台词（提示级）。schema、编号、悬空引用、硬约束（人物/地点数、禁止题材）、整理后超过编辑器 2 万字上限的分集在**生成时**就拒收（不截断）。
- AI 审阅：独立系统提示与评价标准；证据在目标文本中找不到的问题保留展示但**不采用**（不阻塞、不驱动修改）。分数只作内部参考。
- 通过条件由程序判定：没有高严重度的程序问题，也没有已核实的高严重度 AI 问题。模型自己的 verdict 只记录。
- 修改：默认最多 2 轮（可选 0–2），每轮最多改 min(N,3) 集，只改有阻塞问题的分集，然后整体复查。整轮调用必须在本任务预算内才会开始；轮次或预算用完仍不合格 → `quality = needs_work`（「待完善」），保留成果和具体问题，绝不改成通过。设定/大纲层面的问题无法靠改单集解决 → `unrevisable_issues`。
- 修改后，基于旧版本写成的后续分集标记「上游内容已修改，这一版需要复核」（`upstreamChanged`），旧版本标记被哪个版本取代。

## 5. 预算与供应商

- 正常调用：N+5（研究、选题、设定、大纲、N 集、1 次审阅）。最坏：N+5 + 轮数×(min(N,3)+1)。硬上限（含人工确认的 2 次续跑重发）：最坏 + 2。1 集默认：正常 6，最坏 10，上限 12。6 集：正常 11，最坏 19，上限 21。
- 用户可在 [正常, 硬上限] 内设预算；低于正常次数在页面和服务端（400）都拒绝，**不创建任务、不发送**。
- 每次发送前在工作区调用锁内原子预约：任务预算、工作区 24 小时上限（与标题创作、在线候选共用计数）任一不足即停在发送前。开始时还检查剩余次数 ≥ 正常次数，否则 429 且不创建任务。没有提高任何管理员限额。
- 每次输出上限 4096 tokens；提示超过 40,000 字不发送（`prompt_too_large`）。
- 没有可靠价格：只承诺调用次数和 token 上限，`billing_status` 恒为 `unknown`。调用结果未知（state=unknown）与费用未知是两个字段。
- 默认供应商取后台实际配置；配置的默认不可用时 503 并说明缺项，**不改投**其他服务。任务冻结供应商和模型；DeepSeek 新任务写入 `providerAdapter` 标识，无标识的 DeepSeek 任务永不发送。

## 6. 持久化、幂等与恢复

- 表（迁移 `20261019000100_auto_creation`）：`auto_creation_run`（冻结输入、授权方式、预算、已用次数、修改轮次、质量、故事保存）、`auto_creation_stage`（每阶段输出、输出哈希、`depends_on_json` 依赖版本、剧本写入状态）、`auto_creation_call`（每次真实发送一行、usage、unknown 费用）、`auto_creation_resume`（续跑键与确认的不确定调用）。
- 开始：`Idempotency-Key` + 输入哈希（授权方式不计入身份）。同键同内容返回原任务；同键不同内容 409；作品已有故事或已有自动任务 409，不覆盖。页面先把冻结请求和两把键写入会话存储并读回，刷新后只能原样重试。
- 执行：API 进程内按租约运行；已完成阶段绝不再调用；超时/断线/5xx/执行者丢失 → unknown，任务 `needs_attention`，**不自动重发**；续跑必须正好确认当前的不确定调用，续跑键重放只返回当前状态。无效 JSON 等明确拒收 → 停止，不追加修格式调用。
- 重启：维护循环 15 秒一次，只接管租约过期的任务；已预约未发送 → 安全重来，已提交 → unknown。开关关闭时只做隔离（fence），不发送。

## 7. 自动完成与人工审核

- 运行记录 `authorization`：`mode=auto`、`proof=site_session|operator_token`、`initiatedBy`、`executor=auto-creation-engine`（服务端写入，客户端无法携带）。
- 完成后通过受控入口把故事存为 **DRAFT** 故事版本，正文首行写明「AI 自动创作草稿｜机器生成，机器质量检查不等于人工审核」，`created_by = auto-creation:<runId>`（机器身份，不冒充人）。作品已有故事 → `story_conflict`，不覆盖，剧本包照常可下载。
- 剧本写入分集仍要求**人工审核通过**的当前故事（沿用原审核和写入门槛）；一次写入全部分集的当前版本，已有剧本的分集记冲突不覆盖，重复写入不产生新版本。
- 页面分开显示：剧本包、机器质量检查（内部参考）、人工审核、视频成片。完成不等于允许发布。

## 10. 迁移 `20261019000100_auto_creation`

- 只新增四张表及索引，不改任何已有表、约束、函数或数据；与拆解迁移是否执行无关。依赖：七个基础迁移（`GUARDED_SINGLE_MIGRATIONS`）。
- 锁：只有 CREATE TABLE；外键对 project / story_revision / script_revision 取 SHARE ROW EXCLUSIVE 直到事务结束，不扫描、不重写。
- 执行（单独授权；**不要**运行默认 `migrate`，它会带上拆解迁移）：

```bash
DATABASE_URL=<业务库连接串，只在进程环境中> pnpm --filter @ai-drama/database migrate -- --only 20261019000100_auto_creation
```

  测试站组合预期输出 `Applied 1 migration(s).` 与 `"leftPending":["20261012000100_script_breakdown"]`；再次执行 `Applied 0 migration(s).`。
- 未执行时：options 显示迁移缺失，开始返回 503，零写入零发送；其他功能不受影响。
- 回滚：无 down migration；回退代码时保留表（旧代码不读取），关闭 `AUTO_CREATION_ENABLED`，forward-fix。
